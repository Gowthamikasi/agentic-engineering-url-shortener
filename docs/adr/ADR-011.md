# ADR-011: Replanning: invalidate and regenerate the downstream closure

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-09-29 |
| Decision owner | Madhu |
| Reversibility | Medium |

## Context

What happens when an upstream artifact is superseded after downstream nodes have consumed it?

## Options considered

| Option | Assessment |
|---|---|
| Restart the run | Simple, and throws away human decisions that are still valid. |
| Invalidate the downstream closure and regenerate it under a new definition version | Preserves unaffected work and unaffected approvals. |

## Decision

**Invalidate-and-regenerate**: compute the transitive set of nodes downstream of the superseded node, invalidate them, increment the definition version, and re-run them.

## Rationale

Restarting would be easier to implement and would discard approvals that nothing has invalidated - the opposite of preserving governance. Governance survives replanning because the replan is itself a journalled event carrying the version diff and the node list, any gate whose inputs changed returns to awaiting approval, policy evaluation always re-runs, and the new definition version appears on every subsequent audit row.

## Consequences

Which decisions can reshape the graph is declared in the definition (`supersedes` on a gate), not inferred by the engine. Scenario C exercises the whole path: a clarification decision supersedes the normalized requirement, which invalidates and re-executes `quality-check` under definition v2.
