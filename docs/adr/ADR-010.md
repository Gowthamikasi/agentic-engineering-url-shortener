# ADR-010: Recovery: rollback versus compensation, classified per node

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-09-29 |
| Decision owner | Madhu |
| Reversibility | High |

## Context

What should happen after a failure that will not be retried?

## Options considered

| Option | Assessment |
|---|---|
| Roll everything back | Uniform, and wrong whenever a side effect has already been observed. |
| Compensate everywhere | Always honest, and needlessly heavy for artifacts that can simply be regenerated. |
| Classify per node in the definition | Each node declares what is actually true of it. |

## Decision

**Per-node classification**: `ROLLBACKABLE` (output can be reverted or regenerated), `COMPENSATABLE` (a side effect was observed and cannot be undone), `NONE`.

## Rationale

Inferring this would be worse than useless. Calling something rollbackable when a side effect has already been observed is exactly the error that makes an audit trail lie about what was undone. So the definition states it, and a test asserts that a rollbackable node emits rollback events and a compensatable node emits compensation events.

## Consequences

A rollback reverts the node's artifacts but keeps its attempt history: clearing the counter would be convenient and would under-report how much a recovery cost. Both paths end at a safe stop awaiting a human, never at a silent continue.
