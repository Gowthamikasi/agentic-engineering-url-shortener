# ADR-003: Persistence: H2 in file mode with Spring Data JPA and Flyway

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-09-29 |
| Decision owner | Madhu |
| Reversibility | Medium |

## Context

How should state persist while keeping a clean clone runnable with no installation?

## Options considered

| Option | Assessment |
|---|---|
| In-memory only | Zero setup, but resume-after-restart could not be demonstrated, and that is one of the behaviours being assessed. |
| H2 in file mode + JPA + Flyway | Real transactions, real migrations, survives a restart, no installation. |
| PostgreSQL via Docker | Closest to production, but requires Docker and a running container before anything works. |

## Decision

**H2 in file mode**, behind Spring Data JPA, with Flyway owning the schema. Repository interfaces are declared in the domain, so the adapter is replaceable.

## Rationale

File mode is what makes the journal durable across a restart, which is the difference between claiming a run can be resumed and showing it. Flyway owns the schema and Hibernate is set to `ddl-auto: none`, so the schema can never drift silently from the migrations a reviewer reads.

## Consequences

H2 concurrency characteristics differ from PostgreSQL, so the concurrency test proves correctness of the code under H2 rather than under a production engine. A PostgreSQL profile is a configuration change plus a migration review.
