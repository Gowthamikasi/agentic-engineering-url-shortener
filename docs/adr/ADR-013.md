# ADR-013: Testing: JUnit 5, MockMvc, ArchUnit, H2 in-memory

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-09-29 |
| Decision owner | Madhu |
| Reversibility | High |

## Context

What test strategy covers behaviour, contract and structure without Docker?

## Options considered

| Option | Assessment |
|---|---|
| JUnit 5 plus Spring Boot Test plus ArchUnit plus H2 | Fast, no containers, and can assert structure as well as behaviour. |
| Add Testcontainers | Closer to production persistence, at the cost of Docker being required to build. |

## Decision

**JUnit 5 with AssertJ for behaviour, MockMvc for the API contract, `@SpringBootTest` on a random port for integration, ArchUnit for the module boundaries, and H2 in-memory for persistence slices.**

## Rationale

The plane separation is a headline claim, so it is asserted by a test rather than described in a document - `ArchitectureBoundaryTest` fails the build if either plane grows a dependency on the other. The engine's governance guarantees are covered by negative tests: what matters is that approving without a decision, retrying past the budget and resurrecting a failed node are not expressible.

## Consequences

205 tests run in about three minutes with no Docker, so a clean clone verifies itself. Sixteen of them are true integration tests on a real port, run by Failsafe in `verify`; MockMvc alone would not show that redirects, the filter chain and the analytics queue behave in a servlet container. JaCoCo produces a report but no coverage threshold gates the build: coverage is evidence, not a target to farm.
