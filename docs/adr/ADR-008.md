# ADR-008: Human approval: REST endpoint plus a thin CLI

| Field | Value |
|---|---|
| Status | Accepted |
| Date | 2026-09-29 |
| Decision owner | Madhu |
| Reversibility | High |

## Context

How should humans make the decisions the engine must not make?

## Options considered

| Option | Assessment |
|---|---|
| A chat prompt | Natural, and unauditable and unscriptable. |
| REST endpoint plus a CLI wrapper | Auditable, testable, and usable from a terminal or a pipeline. |
| Email approval | Familiar, and needs infrastructure this prototype does not have. |

## Decision

**`POST /workflows/{id}/gates/{gateId}/decision`**, plus a picocli CLI (`gate-cli`) that posts to the same endpoint.

## Rationale

The decision row is written before the node transitions, in that order, so a state change cannot exist without the decision that justified it. Both `actor` and `rationale` are required and refused when blank: an approval with no stated reason is indistinguishable from a rubber stamp when the run is reviewed months later. The CLI is deliberately thin - it can do nothing the API would refuse.

## Consequences

Decisions are queryable, replayable and attributable. The cost is that authentication is an API key (ADR-015), so the recorded actor is asserted by the caller rather than proven.
